□ □ □ 你的第一个开源贡献, 一步步

1. 寻找一个方便初学者的项目

- https://goodfirstissue.dev——各项目配制的`good first issue`
- GitHub主题搜索:[`good-first-issue`](https://github.com/topics/good-first-issue)
- Docs和翻译是最容易的切入点——每个项目都想要它们

2. 了解工作流程

```
fork → clone → branch → edit → commit → push → pull request → review → merge
```

-**Fork**=您自己的服务器侧副本,您可以推向
-**Branch**=不要在`main`上工作 永远不要
- **PR**=您的提议+围绕它的讨论

3. 被接受的公关

- 先看`CONTRIBUTING.md` - 总是
- 每个公关换一个小节奏
- 解释**为什么**,不仅仅是什么——维护者合并上下文,而不是代码
你放弃的公关就死了

4. 先安全练习

热身在设计好的沙盒上(没有判断力,

- [第一-拉-请求] (https://github.com/aixisstudio/first-pull-request) - 你的第一个PR
- [加上你的名字](https://github.com/aixisstudio/add-your-name)——加入贡献者墙

5. 升级

- 问题——复制——修正:信任阶梯
- 回答讨论——维护者记得帮助者
- 一致性击败暴发:一个小型公关/周建立真实的简介

# # 如何读取陌生的密码库 #

1. `README.md` + `CONTRIBUTING.md`——意图
2. `git log --oneline -50`——什么正在积极改变
3. 测试 - 记录行为比文件要好
4. 找到切入点,遵循一个端到端的请求
5. `rg "TODO|FIXME|HACK"`——维护者知道它很痛的地方

你的第一个公关——礼仪

- ** 小型受尊重**:破伤寒修复 > 半断功能
- ** 阅读最后10个合并的公关**:他们教授项目的审查风格
- ** 不要问"我能做这个吗"**:只要打开公关或评论一次,简短地说
- ** 常规承诺**:`feat:`、`fix:`、`docs:`——先检查记录
- **CI 红色=不可合并**:先在当地检查
